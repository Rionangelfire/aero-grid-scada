# Security audit — AERO-GRID SCADA simulator (`index.html`)

Date: November 16, 2026. Method: static read of the assembled file
(1,993 lines), verified by grep. This is a code review of a single
browser-local HTML file. **It is NOT a penetration test.** No live attack
testing was performed, and no backend exists to test — there is no server,
no account system, and no data leaves the browser.

## Summary

No exfiltration path, no code-execution sink, and no user-controlled input
reaching the DOM was found. The only network requests are the two CDN
loads in the page header (Tailwind CSS and Google Fonts). All persistence
is same-origin IndexedDB in the visitor's own browser. One residual note
on `innerHTML` is recorded below; it is low severity and bounded by the
fact that every interpolated value is generated by the app itself.

## 1. `innerHTML` uses and their data sources

Six `innerHTML` assignments exist in the file. Each was read and its data
sources traced.

| Line | Site | Interpolated data | Source of the data |
|---|---|---|---|
| 758 | `addLog` entry | `timeStr`, `message` | `timeStr` is a clock string built from `Date` parts. `message` comes from 23 call sites — every one is a hardcoded string, or a hardcoded string interpolating an app-generated value: mission IDs (`crypto.randomUUID`-derived `MSN-XXXXXXXX`), numbers (`collisionCount`, `kiteCount`, zone ids, kite numbers). No call site interpolates anything the user typed. |
| 1574, 1582 | Mode badge (replay/live) | None | Fully hardcoded HTML strings. |
| 1709 | Fault-frequency bars | `name`, `count`, `pct` | `name` is a key of a hardcoded six-entry object literal (the fault names). `count`/`pct` are numbers summed from stored `faultBreakdown` values, which the app itself writes as numbers. |
| 1726 | Mission archive table | `m.id`, `m.durationSec`, `m.maxWind`, `m.energyMWh`, `m.faultsTriggered`, `m.nearMisses` | Mission records the app itself wrote to IndexedDB: `m.id` is a `crypto.randomUUID`-derived ID; all other fields are numbers computed by the simulation. |
| 1739 | Incident reports list | `inc.cause`, `inc.missionId`, `inc.timestamp`, `inc.riskScore`, `inc.windSpeed` | Incident records the app itself wrote: `cause` is one of seven hardcoded strings (six fault labels + `'Proximity / Airspace Breach'`), `missionId` is a UUID-derived ID, `timestamp` is an ISO date string, the rest are numbers. |

Key structural fact: **the page has no text inputs at all.** The only
`<input>` elements are a checkbox (geofence toggle) and a range slider
(fleet density, min 4 / max 24 / step 1). There is no channel by which a
visitor can type text that reaches `innerHTML`.

Residual note (low severity, stated plainly): the interpolated values are
inserted without escaping, so the safety of these six sites rests on the
fact that every value is app-generated. If hostile strings were planted in
the same origin's IndexedDB by *other* same-origin code, they would render
unescaped in the dashboard tables. In normal deployment this file is the
only page on its origin and nothing else writes that database, so the
exposure is theoretical. No change was made — the task forbids altering
sourced lines — but a future hardening pass could switch the dashboard
rendering to `textContent`/element construction.

No `outerHTML`, `document.write`, or `insertAdjacentHTML` uses exist
(verified by grep).

## 2. External requests

Exactly two external URLs exist in the file (verified by grep over all
`https://` references):

1. `https://cdn.tailwindcss.com` — Tailwind CSS Play CDN (styling).
2. `https://fonts.googleapis.com/css2?family=Inter&family=JetBrains+Mono&display=swap` — Google Fonts stylesheet (which in turn loads font files from Google's font CDN).

No other external requests. No analytics, no tracking pixels, no
third-party scripts. The page will not load its styling or fonts without
internet access, but the simulation logic itself is fully local (verified:
the headless run of the deliverable with unreachable CDNs still ran all
simulation checks — see TEST-REPORT.md).

## 3. Code execution sinks

- No `eval(`, no `new Function(`, no string-argument `setTimeout` /
  `setInterval` (verified by grep).
- No `fetch(`, `XMLHttpRequest`, `WebSocket`, `navigator.sendBeacon`, or
  `new Image` beacon (verified by grep). The page makes no network calls
  from its own script at all — the only requests are the two header loads
  above.
- The Export JSON feature builds a `Blob` from the app's own telemetry and
  triggers a local download via an anchor click. It uploads nothing.

## 4. Storage and persistence

- IndexedDB only: database `AeroGridDigitalTwinDB`, version 1, opened at
  exactly one call site. Three object stores: `missions` (keyPath `id`),
  `incidents` (auto-increment), `exports` (auto-increment).
- Same-origin and browser-local: records persist only in the visitor's own
  browser, on the origin serving the file. No sync, no server copy, no
  account. The Purge DB button (with a native confirm dialog) clears all
  three stores.
- No `localStorage`, `sessionStorage`, or cookies (verified by grep).
- No credentials, no personal data, and no PII are collected, stored, or
  transmitted. Mission/incident records contain only simulation values
  (UUIDs, timestamps, wind speeds, energy figures, fault labels, kite
  snapshots).

## 5. Other observations

- The purge action is guarded by a native `confirm()` dialog ("Delete all
  archived missions, incidents and export receipts?").
- The page requests no browser permissions (no geolocation, camera,
  microphone, notifications).
- The canvas mouse handlers (kite click, zone drag) operate only on the
  simulation state; they send nothing anywhere.
- The `crypto.randomUUID()` mission-ID generation has a `Math.random()`
  fallback for older browsers. IDs are simulation labels, not security
  tokens; the fallback is acceptable for that purpose.

## Verdict

For a single-file, browser-local simulation with no backend and no user
accounts, the file's security posture is sound: no exfiltration, no
injection channel from user input, no dynamic code execution, and storage
confined to the visitor's own browser. The one residual — unescaped
`innerHTML` fed only by app-generated values — is noted above for a future
hardening pass and does not change the verdict.
